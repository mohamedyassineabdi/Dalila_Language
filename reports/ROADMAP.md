# Roadmap and model decisions — 26 November 2026

## Architecture
Audio -> local multilingual ASR or explicit Tunisian route -> editable original transcript. Text -> retain original + conservative normalization -> language/dialect candidates -> intent/slots -> separate validated AFI retrieval/business logic -> grounded reply rendered in chosen language -> optional TTS. Never translate automatically into English. Compare raw Arabizi, transliteration and direct understanding with human-rated paired trials. Preserve names/numbers/units/dates/negation and ask clarification when uncertain. No AFI data is sent to cloud. Models selected provisionally; use version hashes, model manifests and license review before release.

## Shortlist (published claims, not independently replicated)
- Previous ASR baseline: TheBiggyBang/whisper-small-tunisian-derja-ct2 (~250 MB INT8 according to author); CPU candidate. https://huggingface.co/TheBiggyBang/whisper-small-tunisian-derja
- montachouig/whisperX-tunisian: CT2 indexed, direct repository unavailable here. Verify model card, config, file size, revision, conversion origin, supported output scripts, license, inference status and source dataset locally. Same author's whisper-large-v3-tunisian adapter reports WER 21.743907, Apache 2.0, rank-32 LoRA, LinTO named but detailed holdout metadata missing. Cannot transfer WER/license to export without proof. https://huggingface.co/montachouig/whisper-large-v3-tunisian
- oddadmix/Whisperv3-tunisian-codeswitch: full large-v3 fine-tune, NADI 2026, validation WER 17.26%, CER 6.91%, blind test WER 15.22%; trained with mixed Tunisian/French and TEDx replay. No license verified; test offline after rights clearance. https://huggingface.co/oddadmix/Whisperv3-tunisian-codeswitch
- Whisper small, turbo, large-v3 via Faster-Whisper: generic multilingual baselines. https://github.com/SYSTRAN/faster-whisper. CPU int8 preferred; actual RAM/latency unknown on deployment hardware.
- LinTO Vosk Tunisian ASR: Apache 2.0 declared; candidate low-resource streaming comparator, not integrated. https://huggingface.co/linagora/linto-asr-ar-tn-0.1
- LID: algerian-nlp/NUMALIA (CC BY-SA 4.0 declared, reported 91.79% accuracy/91.59% F1 on its own benchmark), NADI2024-baseline Arabic country dialect ID; compare with a general multilingual classifier (fastText lid.176) for de/en/fr/tr; verify Arabizi and mixed-input coverage separately; no generic Arabic label is sufficient. NUMALIA custom code must be reviewed/pinned, never enable remote code blindly. https://huggingface.co/algerian-nlp/NUMALIA ; https://huggingface.co/VARabi/NADI2024-baseline
- Understanding: Qwen3 4B/8B local via Ollama as multilingual baselines, Labess 7B (recovered native prompt, Arabic-script restricted), ESPRIT-Derja-Qwen3-8B-v2 (Arabizi candidate), TounsiLM 8B adapter (review base license and memory). Compare structured intent+slots, ambiguity and response language; test Q4 vs higher precision on same holdout. Do not prioritize cloud due to privacy; Groq/Gemini free quotas change, and previous Groq failed. No verified current quota or external integration in this release.
- TTS: SILMA Derja F5-TTS model card claims code-switch handling but no formal MOS; old README lists noncommercial license, verify current repository plus upstream before institutional use. XTTS Tunisian also research-only until rights checked. Lahgtna OmniVoice and VoxCPM Tunisian are candidates pending card/license inspection. Generic eSpeak is only baseline. Prefer consented reference and separate worker/env for neural TTS; test intelligibility, MOS 1–5, authenticity 1–5, numbers/abbreviations/locations and latency. No cloned voice without consent. https://huggingface.co/Ghazouaniwala/silma-tts-derja ; https://huggingface.co/oddadmix/lahgtna-omnivoice-v2

## Milestones and proposed gates (not achieved)
1. Standalone skeleton + recovery: complete initial local text/HTTP tests; verify full old ZIP before merging legacy workers. Initial benchmark only, no production decision.
2. ASR shootout: same 100+ consented clips, 8+ speakers across regions where feasible, include at least 30 code-switched utterances and 25 critical-slot cases. Compare coverage, WER/CER, exact entities/numbers/negation and semantic agreement. Compare cold load vs warm latency, RTF, RSS, CPU on target. Provisional gate >=95% successful decode, >=95% critical-slot preservation and >=90% intent agreement on reviewed samples, median RTF <=1 on target; revise with stakeholders, not a guarantee. Route unclear audio to clarification, not guesses.
3. LID/understanding: expand authentic text to >=50 per language plus 100 mixed cases; reserve independent blind evaluation. Evaluate macro F1, confusion, coverage vs abstention, code-switch token/span labels, named entity exact-match, intent, ambiguity. Proposed gate macro F1 >=0.85 and critical-slot >=95%; separately check each dialect. Implement local LLM structured schema and constrained grounding, response language override, conversation language switching. No facts without retrieved source.
4. TTS: compare native model candidates on 30 reviewed sentences, 5+ fluent raters if feasible. Human intelligibility, dialect authenticity, naturalness, critical pronunciation and latency; license gate mandatory. Test general-language voices for all supported languages. Generic Arabic fallback must be clearly labeled as non-Derja.
5. Integration: agree API contract with teammates, connect only approved AFI facts, cite source, confirm legal/price/deadline data, bounded retries and timeouts, private logs, concurrency and security tests, Docker build on target. Measure end-to-end p50/p95, memory, CPU, storage. No production release until all quality, security, and license gates are satisfied.
